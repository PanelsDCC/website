Get Involved in Testing

Help us expand controller support

PanelsD.CC is currently in a testing phase, and it would be fantastic if any willing volunteers can help test the gateway application and controller support.

What needs Testing

The gateway application is the bridge between your physical DCC layout and the PanelsD.CC cloud platform. While it is currently designed to run on a Raspberry Pi connected to your DCC controller.

The gateway is built on top of JRMI's JRMIX abstraction layer — the component of JRMI that handles connections to different DCC controllers. This means PanelsD.CC can take advantage of JRMI's broad controller support rather than re-implementing it from scratch.

Important note: PanelsD.CC only uses JRMI for controller connectivity. It does not use JRMI's data models, configuration systems, or features like sensor handling and automatic running. PanelsD.CC is a completely separate system that happens to use JRMI's controller abstraction layer.

The gateway is open source and available on GitHub: dcc-io-daemon. If you're feeling brave, you can check out the README and try installing it on other platforms — we'd love to hear how it goes!

The README in the GitHub repository contains all the details on how the gateway application works and the API that PanelsD.CC uses to communicate with it. In theory, you could even write your own application to interface with PanelsD.CC — but trust me, it takes a long time!

Why Your Help is Needed

PanelsD.CC is a hobby project that has taken two years to reach this point, developed alongside a full-time job and raising a toddler (as mentioned in the future features section). This means there's no big team or investment behind it — just one person working in their spare time.

One of the biggest challenges is limited access to different DCC controllers for testing. During development, testing has been done with a Hornby Elite controller, which works well and even auto-detects when connected to the Raspberry Pi — a zero-configuration setup!

However, to make PanelsD.CC useful for more people, we need to test and verify support for other controllers. This is where you come in.

Expectations

PanelsD.CC is a hobby project that has taken significant time and investment to reach this point. I believe systems like this might help get more people into the hobby, and I'm committed to making it work.

For any volunteers who are genuine and willing to help, I will accommodate as much as I can. However, there are some practical limitations:

Ideal volunteers:

  • Have confidence working with software in development
  • Have experience connecting controllers to PC systems
  • Ideally have experience with connecting controllers to JMRI and know what works for their setup

Even more ideal:

If you're adept with the JRMIX abstraction layer or confident using AI coding tools (such as Cursor) to contribute directly to the gateway code, you could help by submitting pull requests to add support for your controller. This would be incredibly valuable and would help expand controller support much faster.

Alternatively, if you're willing to lend a controller (with the necessary PC connection components), I'm open to that as well. This would allow me to test and implement support directly.

Time constraints:

I don't have time to walk people through more than what's provided in the instructions here, especially if it is related to controllers I don't own. If you're comfortable following technical documentation and troubleshooting on your own, you're exactly the kind of volunteer I'm looking for.

Important disclaimer:

This testing software comes without warranty and I cannot be held responsible for any damage or loss that may be in any way claimed to be related to testing. You're testing at your own risk, using your own equipment.

What You'll Be Testing

If you're willing to help, you'll be testing:

  • Gateway installation on a Raspberry Pi
  • Controller detection and connection with your specific DCC controller
  • Basic train control Train 3 - speed, direction, functions
  • Accessory control Accessory 1 - open, closed
  • Stability and reliability during operation

The gateway includes a configuration web interface that runs locally on the Raspberry Pi, allowing you to configure the gateway and test controlling train 3 and accessory 1.
